# Pi Screenshot Context

独立 Pi 扩展：**只向模型发送当前待分析的手机截图，已分析的旧图不再发送；历史文字照常保留，Web/JSONL 历史图片不删除。** 不修改 Pi、RPC、Web 或手机插件，不增加模型调用，不需要新的运行时依赖。

已在 **Pi 1.4.0、Node 22.23.2** 上验证。其他 Pi 版本尚未验证；本包使用 `context` 和会话自定义条目接口。

## 安装

在实际运行 Pi 的环境中执行（以下是操作说明，项目不会自动修改你的安装）：

```sh
pi install /app/Pi-Extension-Screenshot-Context
```

本地路径安装不会复制目录，所以这个路径必须长期存在。也可以仅为当前项目安装：

```sh
pi install /app/Pi-Extension-Screenshot-Context --local
```

项目安装需获得 Pi 的项目信任。临时试用可使用：

```sh
pi -e /app/Pi-Extension-Screenshot-Context/index.ts
```

在空闲状态重新加载扩展，或重启/重新打开 Pi 会话。已经打开的进程不会仅因磁盘上安装了扩展而自动启用它。

### Web + RPC

**安装到 RPC 服务端使用的 Pi 配置中，不是在浏览器或截图 API 服务中安装。**

- 上面的路径必须在 RPC 运行环境内可见；如果 RPC 在容器中，使用容器内的持久化路径。
- 安装命令必须使用与 RPC 相同的用户和 agent 配置目录。不同 HOME 或 `PI_CODING_AGENT_DIR` 会使安装位置不同。
- 按现有 RPC 的扩展重载流程操作，或在安全停止任务后重启服务/运行时。
- Web 应通过现有扩展命令机制执行命令并展示通知。这里没有新增 Web 界面；生产 Web/RPC 端到端展示需单独验收。
- 若命令未出现，先确认扩展已经被该会话加载，而不是向模型询问是否开启。

## 使用

**新会话默认关闭，开启状态按会话分支保存。**

```text
/screenshot-context on
/screenshot-context status
/screenshot-context off
```

- `on`：开启后省略已经被后续成功模型响应消费的截图，保留尚未成功分析的截图。空闲时开启，不需要新建会话。
- `status`：显示当前开关、过滤目标和待分析截图规则，不调用模型。
- `off`：停止过滤，后续请求可能重新发送历史截图；不需要恢复文件，因为历史文件一直没变。
- 开关仅允许空闲时修改；重复 `on` 不重复写设置。开关不会改变已经发出的请求。
- 开关只保存少量非模型自定义条目，不复制图片或保存图片 ID 列表。恢复会话、分支切换时从当前分支重建设置，并按待发送消息顺序判断图片是否已消费。

## 图片何时过期（0.2.0）

不再按用户任务切分，也不是始终保留最后一张图片：**截图保留到后续模型成功响应，然后仅在待发送副本中省略。**

| 操作 | 发给模型的图片 |
| --- | --- |
| 工具返回截图 A | A |
| 模型成功分析 A，返回文字或下一步工具调用 | 后续请求不再携带 A |
| 工具返回截图 B | B，不携带 A，即使仍在同一次用户任务内 |
| 同批多个工具返回截图 | 保留全部尚待分析的截图 |
| 请求失败、取消或中断后重试 | 仍保留尚未成功分析的截图 |
| 没有新截图、已有截图均被成功分析 | 不发送手机截图 |

Pi 的 assistant `stopReason` 为 `stop` 或 `toolUse` 视为完整成功响应；`error`、`aborted`、`length`、`pending`、`deferred` 及未知状态不视为消费成功，保守保留待分析图片。这个状态判断不保证模型真的理解图片，只表示模型调用已完整成功返回。

用户输入、steer 和 follow_up 本身不决定图片是否过期，因此不再需要区分队列投递类型，也不依赖发送次数或进程内计数器。若一次截图分析一直失败，它会保留到后续成功响应，可能跨用户输入重试。

升级自 0.1.0 时沿用已有开关（已开启会话将立即采用新规则）；旧任务分界条目不再使用，无须删除或迁移历史文件。模型后续无法直接回看旧图进行视觉比较，应参考已有文字或重新获取所需图片。

## 过滤范围和安全边界

- 仅处理 `toolName === "phone_screenshot"` 的 `toolResult.content` 中的 `image` 块。
- 已消费的图片块替换为短文字标记。原有工具说明文字、模型分析文字、工具调用 ID、顺序和对应关系不变。
- 用户上传图片、`read` 等其他工具图片不处理。
- 插件在每次模型请求前运行；本次没有调用手机工具，也会过滤历史手机截图。
- 必须保持**本过滤扩展**加载且开启。原手机插件不加载时，历史 `phone_screenshot` 仍可过滤。
- 不修改原始消息、图片质量或截图接口，不压缩/删除历史记录，不改变 Web 图片加载地址。
- 同批待分析图片仍可能很多；该功能不保证请求体固定大小，也不解决上游账号延迟或故障切换。
- Pi 自己的压缩/恢复逻辑仍可独立改变上下文；本扩展不阻止宿主压缩，也不保证覆盖宿主的摘要生成等独立模型请求。
- 其他扩展若在本扩展之后重新注入图片，可能改变最终请求；需要对实际扩展组合做验收。
- 这是性能优化，不是安全脱敏机制；扩展卸载、未加载或处理失败时不能保证旧图片不被发送。

## 卸载

先在需要恢复原行为的会话执行 `/screenshot-context off`，然后在安装环境执行：

```sh
pi remove /app/Pi-Extension-Screenshot-Context
```

如果是项目安装，移除时也添加 `--local`。重载或重启后不再过滤。会话中的少量设置及旧版边界条目无需删除；它们不进入模型上下文。如果重新安装，同一分支原有设置可再次生效。

## 测试

遵守本项目的 Docker-only 执行约束：测试不能在本地 Pi 工作容器执行。使用独立 Docker 容器，加载真实 Pi 1.4.0 SDK，在容器内准备 `node_modules` 中指向宿主提供包的链接，再运行：

```sh
PI_OFFLINE=1 npm test
```

测试使用 Node 内置测试器和 TypeScript 类型剥离，不安装运行时依赖；需能解析容器内的 `@earendil-works/pi-coding-agent` 和 `@earendil-works/pi-ai`。SDK 测试除公开包 API 外还使用版本绑定的扩展加载器，因此测试基线是 Pi 1.4.0。

覆盖请求投影、输入不变性、开关及旧版设置兼容、真实 SDK 扩展加载、分支恢复、压缩投影、多次截图、失败/不完整响应、队列输入和实际 AgentSession 多轮请求。模型传输使用确定性本地替身，不请求外部 API。实际浏览器展示、生产网络耗时与账号切换需要另行验证。
